Every request records how much it did not cost, and why. We split by strength of evidence: verified savings (the same model cost less — observable) and counterfactual (we served a different model than requested and compared against what the request would have cost). Only verified savings depend on no assumption.

Every model is a route: an alias your code calls that points to a provider. Swapping the provider behind it does not change a line of your app.
How we handle pricing. Every model starts with the provider's public list price, pre-filled — the conservative assumption, because that is what anyone pays without negotiating. If you have a contract discount (EDP on AWS, committed-use on Google, a direct deal with the provider), edit the values below: the model is then marked as contract price and every cost and savings calculation uses your price.
This matters because we have no access to your invoice. While the price is list price and you have a discount, the cost we show is above the real one — and savings are inflated in the same proportion. Every request records which price was used, so history stays auditable after you register the contract.

🟠 Amazon Bedrock
AWS models (Nova, Claude, Llama…) run in your own AWS account (BYO, cross-account): spend, quota and data stay with you. The platform does not resell models from its own account.
The model_id is what goes to Bedrock; the alias is what your code calls. Use a short, friendly alias (e.g. claude-sonnet) — that way you can swap the model behind it without touching your app. Prefix caching (prompt caching) is enabled per model in the route list below.

Nothing is created in the platform account — you own and control this role end to end.

Swap policy per feature
How far the gateway may go when it cannot serve the route you asked for. It binds every path that substitutes a model — cost optimization, provider fallback and budget degrade. When nothing can serve within the ceiling, the request is refused with its own code instead of silently receiving a different model.
Fallback bundles
An ordered set of layers: try these first, then those. Referring to a model identity covers every route serving it, so adding a provider tomorrow needs no edit here. A bundle only reorders what is already allowed to serve — it never promotes a route into a request it cannot handle.
